1. WHAT THIS PROJECT IS
============================================================================
A single-file Streamlit web app built for the Siliguri Institute of
Technology (SIT) institutional exhibition. It works 100% OFFLINE.

It combines:
  - Role-based register/login  (Student / Staff-Admin / Parent)
  - Anonymous wellness check-ins (pseudonymous SHA-256 tokens)
  - Milestone / deadline tracking
  - Grievance reporting -> department-route -> status workflow
    with a TAMPER-EVIDENT hash-chain audit trail
  - Staff wellness analytics, meeting (appointment) slots
  - Parent / public timeline, burnout guide, transparency ledger

Tech: Python + Streamlit, SQLite (stdlib), hashlib, datetime, pandas.
Data never leaves the device.

2. FILES IN THIS FOLDER  (F:\College Hub)
============================================================================
  app.py            The entire application (UI + logic + database). ~1500
                    lines. All tunable values are in "SECTION 1: CONFIG".
  requirements.txt  streamlit + pandas. Install once with:
                        pip install -r requirements.txt
  run.bat           Double-click launcher (cd's to folder, runs
                    "python -m streamlit run app.py", pauses on exit).
  sit_hub.db        SQLite data file created automatically on first run.
                    Safe to delete anytime to reset to fresh demo data
                    (it will re-seed itself on next launch).
  __pycache__       Generated python cache - ignore.
   backups\          Auto-created on launch (laptop only). Keeps the last
                     MAX_BACKUPS (10) timestamped copies of sit_hub.db so the
                     durable local copy is effectively loss-proof.

3. HOW TO RUN / STOP
============================================================================
  - Double-click  app.py   OR   run.bat
  - A console opens, the browser auto-opens on http://localhost:8501
  - To stop: press CTRL+C in the console, or just close the window.

  (app.py has a guard: if it is run as a plain script instead of via
   "streamlit run", it relaunches itself through Streamlit automatically.)

  NOTE on the first-ever run: Streamlit once asked for an email address.
  That was answered with a blank email, so it will NOT ask again.

  The blue-text "NativeCommandError" lines in PowerShell when booting are
  only PowerShell complaining about Streamlit writing logs to stderr -
  they are harmless and the app is still working.

6. DATA LAYER & RESET
============================================================================
SQLite tables created on boot (see DB.create_tables):
  users  wellness_logs  milestones  grievances  grievance_audit
  meeting_slots  academic_deadlines  app_meta

Seeding:
  - Guarded by app_meta key "seeded" -> seeds exactly once ever.
  - To regenerate demo data (e.g. after changing seed text or departments):
      1. Stop the app.
      2. Delete  sit_hub.db
      3. Restart - it re-seeds automatically.

Demo data (3 demo users, ~184 wellness logs across 11 departments,
6 grievance tickets SIT-1000..SIT-1005, milestones, slots, deadlines).

Audit trail:
  - Every status change appends to grievance_audit; each row stores
    prev_hash + audit_hash (SHA-256 of prev_hash|ticket|new_status|who|time|SEAL).
  - render_audit_badge() recomputes the whole chain and shows
    "Audit chain verified" (green) or "Tampering detected" (red).
  - Anyone can check it live - strong demo talking point.

10. WINDOWS QUIRKS
============================================================================
  - Double-clicking app.py works via the auto-relaunch guard.
  - If a streamlit session is killed abruptly (e.g. a tool timeout), an
    orphaned python.exe may keep holding sit_hub.db. To free it:
        Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
        Where-Object { $_.CommandLine -match 'streamlit|app.py' } |
        ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  - The app is verified to compile (python -m py_compile app.py) and the
    DB layer has proven: seeding, login, register, audit-chain integrity
    through a live status update.
